# Checks that mean something

## Falsifiability — every check is proven able to fail

A check that has never been red is a decoration: nobody knows whether it guards anything. The discipline, applied every time a check is born:

- **Red first.** A new check runs against the pre-fix state, or against a deliberately broken input, and is watched failing — *then* the code that turns it green lands. When a check is adopted into a repo whose state already violates it (a stale version number, a drifted list), that first red run on the real violation is the proof; only then align the state
- **Checkers ship self-tests.** A lint harness runs itself against known-bad fixtures (`tests/fixtures/must-fail.*`) and exits nonzero unless the fixtures fail. A pipeline that passes a file with an unclosed quote would also pass a broken template, and its green runs would mean nothing
- **Extractors refuse to find nothing.** A drift check that parses flags, commands or names out of a file fails loudly when its regex matches zero items — a broken extractor must not read as "no drift"
- **Whole-line assertions on generated text.** `grep -qxF`, not substring matches: two similar outputs (a Debian URL that prefixes the generic one, a heading that contains another) make substring checks pass for the wrong branch, provably
- **Un-mute before diagnosing.** When one platform fails where the rest pass, the first move is removing the `2>/dev/null` from the pipeline in question — an older tool rejecting newer syntax vanishes into muted stderr and presents as "empty output"
- **Probe the mechanism, never a proxy.** A feature-detection check must measure the thing the code actually depends on. Asking `wc -m` whether a locale works when `bash` does the counting downstream lets one implementation answer for a locale another implementation never got

## Checkers worth copying

All live in [`templates/`](../templates/). `no-secrets.sh` is a skeleton, and carries the warning in its header: **copying it proves nothing**. The mechanism is reusable; the knowledge is not, and the property that makes it worth running is local — the copy must have been falsified in its own repository. `check-pins.sh` and `check-interface.sh` have no local knowledge to add, so another repository takes them through the [vendoring cascade](bump-cascade.md#vendored-files) rather than by hand — and each falsifies itself on every run, which is the only way a file that travels alone can stay proven. The pin guard is described where its rule is, in [pinning.md](pinning.md); the others below

### `no-secrets.sh` — the gate at the tracked-file boundary

`.gitignore` keeps a file out; this keeps both an ignored path and a secret value out of tracked files. Before scanning contents, it pipes every tracked path through `git check-ignore --no-index`: `--no-index` is what catches a path admitted with `git add -f`, since without it Git deliberately skips tracked paths. A repository with no `.gitignore` produces no ignored paths and passes this part. NUL delimiters preserve every legal filename. It then greps **tracked files only** (`git ls-files`, `-I` so a byte sequence inside an image is not a finding), one branch per shape so the message names what was found, and it exits 0 with `nothing tracked yet` on an empty repository rather than reading as a pass by accident

Most of it is universal and belongs in every copy: PEM private key headers whatever the algorithm label says; forge and registry tokens (`ghp_`, `github_pat_`, `glpat-`, `npm_`, `pypi-`, `hf_`, `dckr_pat_`); model-provider keys (`sk-ant-`, `sk-proj-`, `sk-svcacct-`, `sk-or-v1-`, the legacy 48-character `sk-`, Google's `AIza`, `gsk_`, `r8_`); cloud and SaaS credentials (AWS key ids, `GOCSPX-`, Slack `xox?-` and webhook URLs, `sk_live_`, SendGrid, Mailgun, Twilio, DigitalOcean, Doppler, Linear, Telegram bot tokens); and anything JWT-shaped, which is how a Supabase service key or a session bearer arrives when pasted whole. Under all of them sits the catch-all for providers with no distinctive prefix: a secret-shaped key assigned a real value. Per-repo shapes — a service's session cookie, whole paths that must never be tracked — go in the two `EXAMPLE` sections

**Every pattern must be unable to match its own source line.** The gate greps the tracked files, and its own file is one of them: a literal prefix followed by a bracket expression is safe (`sk-ant-` then `[A-Za-z0-9_-]{80,}` cannot match the text `[A-Za-z0-9_-]{80,}`), a bare literal is not. Keep that property when adding a shape, or the gate reddens the repository on the very commit that introduces it

Falsify it by forcing an ignored path into the index, then planting one value of each secret shape and watching every case go red. This skill does that in `check-templates.sh`: a throwaway git repository, the template copied in and tracked, first a clean run — which is also the self-match test, since the gate is now scanning its own source — then `user/preferences.md` covered by `.gitignore` and added with `git add -f`, which must be named in the finding, then one generated value per shape, each on its own tracked file. The gate must report every case under its own name: a value caught only by some other, over-broad pattern means the pattern meant for it is dead, and "it went red" alone would not tell. The planted bodies are generated rather than committed: a literal key-shaped string in a fixture is a real finding for every scanner that reads the repository, and a fixture that cannot be pushed is not a fixture

### `check-interface.sh` — documents held to the tool they describe

A skill that teaches an agent someone else's tool — a CLI, an MCP server, an API — restates that tool's names in its documents, and nothing the repository runs notices when the tool renames one: the document goes on teaching a call that no longer exists, and the agent learns it. A repository-owned script can be checked against its source; a foreign tool has only what it declares about itself. The gate turns that declaration into a list — from an MCP handshake, `tool help | awk …` or another authoritative interface — and `check-interface.sh -d LIST DOC...` holds every claim the documents make to it. `check-interface.sh --help` carries the notations and the flags that pick them; this is why they are the way they are

- **The document marks a claim; the checker never guesses one.** A claim opens with a prefix the tool's calls carry (`tool search query=…`, `mcp__server__search`), is written in call notation (`search(query, limit)`), or is a code span that is wholly a name of a given shape. An unmarked word cannot be told from prose: `command -v tool` and a quoted line of the tool's output are both code spans that open with a word the tool declares. That is why the lenient notation, a span that merely opens with a declared name, holds only its `key=` arguments and takes its bare words for prose
- **A name the tool stopped declaring is caught even where prose is allowed.** The lenient notation cannot tell a renamed command from an ordinary word, since both are simply undeclared; a hundred-odd bare spans in one skill opened with words no command ever was. What tells them apart is history: with `-r` the gate passes every name the tool declared before, and a claim opening with one that is gone — renamed or removed — is a finding in every notation. The gate builds that list from the declarations it recorded, so a rename is caught in the very commit whose new recording drops the name
- **Arguments are held per name, never as one flat list.** Flattened, a document could give one tool an argument only another tool takes, and pass. A name holding a placeholder, `read_<source>_paper`, stands for every declared name it fits, and each of them must take the argument
- **Nothing to read is refused, not passed.** An empty declared list, or documents in which the notations find no claim, exit 2: a parser that stopped matching must not read as agreement
- **A wrong call shown on purpose is excused outside the document.** A pitfall whose lesson is the typo (`backlinks fil=Garden`) is excused in a file named by `-x`, which no agent loads, rather than by a marker on its line: the documents checked here are the runtime an agent loads whole on every invocation, so a marker there would bill every request for an excuse only the gate reads. An entry names the finding's id and the document, and a text on the line when one line is meant, so it survives edits without a line number; an entry that excuses nothing is itself a finding, so an excuse cannot outlive its line. The pin guard's `# check-pins: allow` stays on its line, since a workflow is not what an agent loads
- **Each notation proves itself, every run, against the consumer's own tool.** The planted documents are built from the declared list the gate passed, read with the same flags: a faithful one must pass, and a made-up name, a made-up argument in each notation, a placeholder, a fenced line and a flag must each go red for their own reason, while, without `-a`, a prefix in passing prose must stay quiet. Each form of excuse is planted beside the defect it excuses — by id and document, by a text on one of two lines, by a fenced line as written — and an entry of the wrong id or document must excuse nothing, a stale one must be reported, and a malformed one refused. A copy is so falsified in the repository that calls it, against the interface it actually checks
- **Where the list comes from decides gate or detector, and that is the consumer's call.** A server the repository's flake packages can be asked in the gate itself. A desktop app with no headless mode cannot run on a runner, so that gate reads a snapshot of the tool's own declaration, committed with the version it came from, and a run where the tool is present diffs the snapshot against the live answer — a hand-kept mirror, drift-checked, as the next section allows

It needs bash 3.2 and POSIX tools only, so it runs on a macOS runner unchanged

## One source of truth per list

Every list CI consults lives in exactly one place; everything else reads it or is checked against it:

- **Lint file lists** live in the build system's own check (a flake check, a make target, a package.json script); the CI job *runs that check* instead of repeating the command with its own copy of the list. Two hand-maintained lists of "files we lint" will disagree within a month
- **The version** lives in one machine-readable file, and CI cross-checks it against the one place it cannot read from — the changelog. This gate applies only to repositories that ship a version
- **Hand-written mirrors are allowed, drift-checked.** Shell completions, documented command tables and README flag lists may be spelled by hand for quality, provided a check derives the authoritative list and fails on divergence in both directions
